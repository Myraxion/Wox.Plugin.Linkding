# Use Smart Input Pattern Recognition Instead of Explicit Subcommands

We decided to route user intent dynamically based on input format rather than requiring explicit subcommands like `ld add` or `ld tag`. Queries starting with `http://` or `https://`, as well as recognized unprefixed URLs (e.g., `woxlauncher.com`, `localhost:8080`, `127.0.0.1:8000`), are normalized with appropriate schemes and treated as bookmark creation workflows. Queries whose active typing fragment (the trailing token) is prefixed with `#` navigate and complete tags with window persistence (`prevent_hide_after_action=True`). In multi-tag workflows, tag candidates are dynamically scoped to co-occurring tags extracted from bookmarks matching the preceding query prefix, preventing zero-result combinations and displaying co-occurrence frequency counts. Completed tag tokens combined with other terms act as a multi-tag bookmark search query. All other text acts as a title/description search phrase. This pattern recognition applies uniformly to search box queries (`QueryType.INPUT`) and text selection queries (`QueryType.SELECTION`). This minimizes keystrokes and cognitive overhead in a launcher environment, trading away explicit namespace separation for immediate intent recognition.

## Considered Options

- **Explicit subcommands (`ld search ...`, `ld add ...`, `ld tag ...`)**: Standard CLI style, unambiguous routing, but slower to type and adds redundant prefixes in a quick-launcher context.
- **Smart pattern recognition**: Automatically distinguishes URL addition and tag exploration by regex / prefix checks while falling back to bookmark search. Unprefixed URLs from browser copy/selection are automatically normalized (`http://` for localhost/127.0.0.1, `https://` for domain/IP). In multi-tag workflows, trailing `#<prefix>` tokens dynamically trigger co-occurring tag browsing scoped to matching bookmarks (excluding unassociated tags), while pressing Enter appends the selected tag and persists the launcher window for seamless query refinement.
